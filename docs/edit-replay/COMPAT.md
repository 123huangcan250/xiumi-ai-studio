# 编辑回放 · 兼容性清单

本文只记录**已经验证的事实**和**待真机验证的项目**。没有真机结果的项目一律标为“待验证”，不要据此宣称“已兼容公众号”。

## 已验证（桌面 Chrome，Playwright 自动化）

| 项目 | 结果 | 依据 |
|---|---|---|
| SMIL：`animate` / `animateTransform` / `set`，`calcMode` 为 `spline` / `discrete` | ✓ 按预期播放；`pauseAnimations` + `setCurrentTime` 可精确定位 | `tests/e2e/replay.spec.ts` 6 个时间点截图基线 |
| 删掉光标层后成稿不变 | ✓ 每个时间点逐像素一致 | 同上：关掉光标层渲染 vs 带光标层渲染后删掉光标层 |
| 动画被过滤时的退化效果 | ✓ 所有文案可见，线框、尺寸标签、光标、过程数字都隐藏 | `tests/unit/replay.test.ts`“退化为静态成稿” |
| 输出中没有 script / style / class / id / `url(#)` / `foreignObject` / `animateMotion` / filter / mask | ✓（自动播放方案） | 单元测试 + E2E 读取剪贴板 HTML |
| 复制到剪贴板（内嵌图片模式） | ✓ 剪贴板 text/html 含完整 SVG 与动画 | E2E |
| **自动播放的起始时机** | ⚠ Chrome 中**所有场景在插入页面时一起开始计时**，不在视口内也照常走时间；不会等滚动到才播 | 2026-11-13 在浏览器中实测：插入到页面下方 20000px 处的 SVG，1.5 秒后 `getCurrentTime()` 为 1.49 |

最后一条意味着：在 Chrome 中，“每个场景独立一个 `<svg>`，往下滚时后面的场景还没播完”**不成立**。读者滚到第二个场景时，它很可能已经定格在成稿。微信内是否相同，需要真机确认（见 C4）。目前可用的办法：

- **循环播放**：场景播完停留 N 秒后整体重放，读者滚到时总能看到过程。
- **点击开始**（方案 A）：依赖 `id` 保留，待验证。

## 秀米 → 公众号实测（2026-11-14，用户在秀米导入探针后同步到公众号，手机预览）

| 项目 | 结果 | 用到的地方 |
|---|---|---|
| `begin="click"`（轻触元素自己） | ✓ | 擦除显影、AI 计算才华、昨天今天明天、星光黎明 |
| `id` + `begin="某id.click"`（同一个 SVG 内跨元素触发） | ✓ id 被保留 | ↻ 重播 |
| 动画 SVG 根元素的 `viewBox`（轻触后收起高度） | ✓ | 开场“开始阅读”之前只显示第一页 |
| 动画 SVG 根元素的 `height` 属性 | ✗ 变形 | 不用 |
| `<use href="#id">` 复用图形 | ✗ 不显示 | 不用；特殊字体只能每个字单独画 |
| 字形路径（站酷庆科黄油体） | ✓ | 大标题 |
| **由另一个 SVG 里的按钮触发**（开头“开始阅读”触发全文） | 待确认 | 全文动画的起点；失败时各模块显示静态成稿，↻ 仍可单独播放 |

## 待真机验证

每项请在 **iOS 微信、Android 微信、PC 微信（Windows / Mac）** 各测一次。另外还要测公众号后台编辑器和手机预览。

测试材料：

1. 用「编辑回放」→「载入示例」生成示例模板。
2. 「导出 / 发布」→「复制到剪贴板」，内嵌图片和上传到微信图床两种模式各测一次。
3. 在公众号后台新建图文并粘贴，然后用「预览」发到手机。

| 编号 | 项目 | 怎么看 | 失败时的处理 |
|---|---|---|---|
| C1 | 后台编辑器是否保留 `<svg>` 及 `<animate>` / `<animateTransform>` / `<set>` 和它们的属性（`values`、`keyTimes`、`keySplines`、`calcMode`、`fill`、`repeatCount`） | 粘贴后保存，重新打开，查看是否仍会动；用浏览器开发者工具看源码 | 记录被删的标签/属性，改用不依赖它们的写法 |
| C2 | **`id` 是否保留**；`begin="场景id.click"` 和 `<set end="场景id.click">` 是否生效（方案 A） | 把「触发方式」切到“点击开始”，导出后在手机上点画面 | 不保留：只用自动播放（默认） |
| C3 | `url(#id)`：`linearGradient` 渐变背景（只在方案 A 输出） | 方案 A + 渐变背景，看背景是否变成黑色或透明 | 改回方案 B 的色带近似 |
| C4 | **自动播放的起始时机**：后面的场景是否在滚动到之前就播完（Chrome 已确认会，见上） | 文章前面放几屏正文，回放放在最后，进入文章后慢慢滚到回放处 | 改用循环播放，或在回放前少放内容 |
| C5 | `calcMode="spline"` + `keySplines` 的缓动、`calcMode="discrete"` 的跳变 | 看光标移动是否急起缓停、故障抖动是否离散跳变 | 退化为线性也能接受，记录即可 |
| C6 | 嵌套 `animateTransform`（缩放套平移、swarm 的旋转 + 反向旋转 + 反向缩放） | 看按钮弹出、图片拖入、收尾绕圈是否位置正确 | 去掉 swarm，改用各自离场 |
| C7 | 文字渲染：栅格图模式（默认，2 倍 PNG）是否清晰；SVG 文字模式的字体、`letter-spacing`、`text-anchor` | 两种文字模式各导出一次 | 用栅格图模式 |
| C8 | `<image href>`（没有 `xlink:href`）能否显示微信图片；`preserveAspectRatio="xMidYMid slice"` 的裁切 | 图片元素选一张横图一张竖图 | 记录后改为同时输出 `xlink:href` |
| C9 | 内嵌图片模式下，后台是否把 `data:` 图片转存为 `mmbiz.qpic.cn` | 粘贴后查看图片地址 | 配置公众号接口，用“上传到微信图床” |
| C10 | **体积上限**：单个 SVG、整篇正文的最大体积；超出时是粘贴失败、截断还是保存失败 | 把单场景预算调大，逐步增加元素，记录临界值 | 把实测上限写回下面的表格，更新默认预算 |
| C11 | 循环播放（`repeatCount="indefinite"`）在低端安卓机上是否卡顿、发热 | 循环模式放 3 个场景 | 只在首屏场景循环 |
| C12 | `stroke-dasharray` / `stroke-dashoffset` 描边动画、`fill-opacity` | 看“线框描出”是否沿边画出 | 退化为直接出现 |
| C13 | 草稿箱接口 | 回放 SVG 远超 2 万字符上限，导出面板会拦下 | 用复制粘贴 |
