# AI 模型发现与选中模块修改

## 模型设置

在「AI 模型设置」填写 Base URL 和密钥；修改完成并离开输入框后会自动获取模型列表，也可点击「从服务商获取模型列表」刷新。仅打开设置或逐字输入时不请求服务商。服务端请求该配置的 `/models`；Anthropic 使用 `/v1/models`（Base URL 可包含 `/v1`）。密钥不会放进 URL，发现请求不会跟随重定向。获取成功后会直接显示可滚动的「可用模型」列表，点击即可填写模型名称及已提供的上下文窗口、最大输出和思考强度列表；无需再点输入框展开建议。选择模型后也可继续手动输入任意模型 ID。

只有上游实际返回的元数据才会导入：`context_length` / `context_window` / `max_context_length` 以及 `reasoning_efforts`。标准 OpenAI 模型列表通常只返回 ID，不提供上下文窗口或思考强度；此时请按服务商文档手动填写，不从模型名称猜测。上下文窗口仅作为配置记录，不会截断或扩充输入。Anthropic 发现最多读取 5 页，每页请求最多 1000 条；其他接口使用单次模型列表响应。未列出的模型仍可手动填写。最大输出会限制单次请求的 token 上限。

思考强度留空时保留现有请求行为。填写时：

- OpenAI 兼容接口发送 `reasoning_effort`，兼容服务优先使用 `max_tokens`，仅官方 `api.openai.com` 的显式思考请求默认使用 `max_completion_tokens`；服务明确拒绝并要求另一输出长度字段时才切换，不静默移除思考强度。
- Anthropic 发送 `output_config.effort`，输出上限仍为 `max_tokens`。
- 两种接口均不发送 `temperature`，避免与部分思考模型冲突。

强度是可编辑字符串，建议值不代表服务商已支持。自定义网关必须兼容所选接口参数；若只支持专有 thinking 开关或 token budget，当前不会自动转换。错误会显示，不会静默降级思考强度。请在保存后测试连接。更换服务地址 origin 或接口类型后，必须重新填写密钥或明确清空以使用无密钥服务；不能把之前保存的密钥自动发送到新服务。

可点击“检测思考强度”发送短测试请求，可能产生 API 费用；不会自动探测。高级额外参数接受 JSON 对象中的服务商专用选项，但不能覆盖模型、消息、工具、流式设置、输出上限、温度、思考强度或 JSON 模式。从列表选择模型时更新其能力元数据；手动输入模型名或更新密钥保留已填写的参数。

## 精确修改

在画布点选模块后打开「AI 设计」，默认范围为「仅选中模块」，界面显示模块内容摘要。服务端默认保留选中模块及容器内子模块的合规修改、允许顶层选中模块附近插入，并丢弃越界操作。被忽略数量会显示在提案中，用户仍须审阅接受。选择「全文」后才允许全文操作。需要整批拒绝语义的部署者可以显式配置 strict，见下文。

修改仍需逐条或全部接受，可以撤销。请求期间若文档发生变化，会要求重新生成，避免把旧建议应用到新正文。范围为整个模块，不是富文本中任意字符选区；导入的 HTML 原文片段仍以模块的文字槽位进行修改。

## 验证

单元测试覆盖模型发现元数据、参数透传、设置持久化、密钥作用域、选中模块提示词和越界结果拒绝。`tests/e2e/ai-issues.spec.ts` 覆盖模型设置持久化和画布选择到 AI 请求的传递，可通过 `pnpm e2e tests/e2e/ai-issues.spec.ts` 运行。真实服务商的能力和返回格式需使用用户自己的配置验证；测试不会调用付费模型。

## 兼容性与边界说明

思考强度由用户显式选择，服务商拒绝该强度时不会静默移除后假装成功。推理请求不发送 temperature，以兼容拒绝自定义温度的模型；如服务商不支持 reasoning_effort，请清空该项并按其文档配置。兼容性回归使用模拟服务商响应，未宣称已联调 DeepSeek、通义或所有 OpenAI 兼容网关。

自动输入建议默认关闭，需在 AI 面板主动开启；开启后会将当前范围的文稿上下文发给所配置模型，并可能产生费用。关闭不影响手动提交 AI 指令。

网页抓取上限为解压后 15,000,000 字节（约 14.3 MiB），超出会返回 413，不返回可能截断标签或遗漏后文的半篇文稿；这是有意的完整性与资源保护边界。请改为导入较小片段或文件。

## 可选的选中范围策略

默认 `AI_SELECTION_POLICY=filter`：保留合法操作，丢弃越界操作并在差异面板报告忽略数量；选中文本框时包含框内子模块，允许在选中顶层模块前后插入。这延续 main 的过滤语义，并补充了锚点、目标有效性与子模块边界校验。

部署者可以显式设置 `AI_SELECTION_POLICY=strict` 并重启，选择整批拒绝语义：允许选中模块及其子模块的 update；混入任何不允许的操作，整批拒绝。strict 是本 PR 提供的可选策略，不是 main 原有默认行为。未设置时使用 filter；非法配置采取 strict，避免拼写错误意外放宽范围。

服务端响应明确返回当前策略，客户端用相同策略再次校验。请求体和模型输出不能切换策略。两种策略都拒绝失效或不匹配的选中目标，不允许整体替换容器 children 或修改框外兄弟、文章全局信息。插入使用稳定锚点，并为所有嵌套新模块重新分配 ID。

两种模式不是等价行为：strict 保持修改批次整体性，filter 可能只形成模型原计划的部分修改。因此过滤结果仍需用户逐条审阅接受，可撤销。独立部署若需要严格策略，应显式设置 strict。
