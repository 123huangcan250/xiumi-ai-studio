# P0 秀米与公众号互通实测

这份清单回答一个问题：**Studio 的内容能否进入秀米继续编辑，秀米的内容能否回到 Studio。**

官方页面写明的能力不等于已经可用。下面的“结果”栏必须由实测的人填写，没有测过就留空，不要写成通过。

## 准备

```bash
pnpm probe
```

样张生成到 `data/compat-probe/`，该目录不进入 Git。每份样张有两个文件：

| 文件 | 用途 |
|---|---|
| `*.html` | 用浏览器打开，复制白色区域的富文本 |
| `*.fragment.txt` | 纯 HTML 代码，粘贴到导入框，或直接上传 |

| 样张 | 内容 | 能否外传 |
|---|---|---|
| 01 | 内置模块，无图片 | 可以，全部原创 |
| 02 | 内置模块，base64 内嵌图片 | 可以，图片来自 `samples/` |
| 03 | 本机模板里的 SVG 片段 | **不可以，私有数据** |
| 04 | 本机模板里的轮播片段 | **不可以，私有数据** |
| 05 | 三种背景图，用于公众号粘贴 | **不可以**，含一张模板里的图片 |
| 06 | 图片矩阵，每行一种来源和格式 | **不可以**，含模板里的图片 |
| 07 | 一张约 1.1MB 的内嵌大图 | 可以，图片是程序生成的噪点 |

秀米和公众号都要用你自己的账号登录操作。是否开通 VIP 由你决定：官方说明写的价格是 10 元/30 天，T1 需要它。

### T1b 图片矩阵：秀米拒绝哪一类图片

导入时如果提示“检测到部分图片无法直接导入，已用占位图替代”，用样张 06 判断是哪一类。

1. 导入 `06-image-matrix-private.fragment.txt`。
2. 每行标题都写明了来源和格式，记下哪几行变成了占位图，保存后重新打开再看一次。
3. 再导入 `07-large-image.fragment.txt`，它就是表里的 B 行。

用户实测结果（2026-11-08）。用户只报告了异常的行，E 到 H、J、L 的显示正常是由此推断的；保存后重新打开的结果没有报告。

| 行 | 内容 | 显示 | 能否选中编辑 |
|---|---|---|---|
| A | 内嵌 JPG（6KB） | ✕ 占位图 | |
| B | 内嵌 JPG（1162KB） | ✕ 图片消失，位置也没有了 | |
| C | 内嵌透明 PNG | ✕ 占位图 | |
| D | 内嵌 GIF | ✕ 占位图 | |
| E | 微信图床 JPG | ✓ | |
| F | 微信图床 PNG | ✓ | |
| G | 微信图床 GIF | ✓ | |
| H | 普通外链 | ✓ | |
| I | 背景图：内嵌 JPG | ✕ | ✕ |
| J | 背景图：微信图床 JPG | ✓ | ✕ |
| K | SVG 背景图：内嵌 JPG | ✕ | ✕ |
| L | SVG 背景图：微信图床 JPG | ✓ | ✕ |

结论：秀米不接受内嵌图片，接受 https 图片地址；背景图能显示，但不能在秀米里单独编辑。导出面板的“导入秀米”据此实现。

下表是实测前列的判断依据：

| 结果 | 修复方向 |
|---|---|
| E、F、G 失败，A、C 正常 | 增加“导出给秀米”：微信图片也由本地服务取回后内嵌 |
| A、C 也失败 | 内嵌图片不被接受，要先传到公开图床（如微信图床）再导入 |
| 只有 B 失败 | 导出前按体积压缩 |
| 只有 D、G 失败 | 动图不被接受，只能导入后在秀米重新上传 |
| 只有 I 到 L 失败 | 秀米只处理 `<img>`，背景图需要导入后重新上传 |

## 如何判断下一步

| T1 结果 | 目标②的做法 |
|---|---|
| 导入后可以结构化编辑 | 在导出面板做“导出 HTML 文件（秀米）”，取消自建临时链接 |
| 显示正确但整体锁定 | 如实标注为“视觉相近”，继续编辑留在 Studio |
| 导入失败或严重错位 | 官方路线不可用，向 support@xiumi.us 询问，不做绕过 |

T3、T4 只有在 T1 不理想时才值得继续投入。

## 本机已验证的事实

这些是在本机实际观察到的，不涉及秀米或公众号后台。

| 项 | 结果 |
|---|---|
| 微信防盗链 | 请求带 `Referer: https://xiumi.us/` 时，微信返回 HTTP 200 和一张 140×140、2090 字节的 JPEG 占位图；不带 Referer 时返回原图（28 个地址逐一实测，占位图大小都相同）。状态码是 200，只看状态码发现不了 |
| 微信图片作为 CSS 背景在浏览器里加载 | 返回同样的占位图，同一地址用 `<img>` 或服务端请求能取到原图，浏览器为何对 CSS 背景不同未确认。编辑器显示时改走 `/api/wx-image` 转发，存储和导出仍是原地址 |
| “微信 HTML（图片内嵌）”导出 | 只内嵌本地素材（`/media/`），微信图床的图片和背景图保持外链，所以同一份导出里两种来源并存 |
| 使用 fake-ip 代理时的 DNS | 所有域名都解析到 `198.18.x.x`，所以这个网段不能算作内网，否则抓取会全部失败 |
| 秀米转存 | 代码路径有测试（模拟响应），**没有用真实的秀米图片测过** |

## 组件库的内容边界

组件库只存在本机的 `data/components/`，不进入 Git。

- 来自公众号或秀米的组件强制标记 `redistributable: false`，收藏时必须确认使用权。
- 不提供分享、导出组件库或公共组件库。秀米用户协议不允许把编辑区素材和风格模板提供给他人，违者可能被封号。
- 不做批量抓取，也不用逆向接口取秀米组件库。组件只来自用户自己导入或粘贴的内容。
- 仓库内置的模块和主题仍全部原创。
