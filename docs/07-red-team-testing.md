# 红队回归测试

## 执行

```bash
pnpm check
pnpm build
pnpm exec vitest run tests/unit/redTeam.test.ts tests/unit/fetchBoundaries.test.ts
pnpm e2e --update-snapshots=none
```

E2E 必须有可用浏览器和本地监听权限。缺少截图基线时应人工审核，不应在 CI 自动更新基线来消除失败。

## 当前覆盖

- IPv4-mapped IPv6 的点分、十六进制与展开写法不能绕过内网拦截；同样检查 DNS 返回地址和重定向。
- 实际 TCP 连接只能使用本次校验通过的地址，不在连接时再次查询 DNS。保留 URL 域名供 HTTP Host、TLS SNI 和证书校验使用。
- 文章抓取上限为 5,000,000 字节，图片抓取/转发上限为 30 MiB。响应声明的传输长度和逐块读取的解压后字节数都不得超过该上限；缺少或伪造 Content-Length 不能绕过限制。
- 使用真实 undici 解压路径验证小 gzip 响应扩张后仍受限制；超过上限取消读取，重定向响应体不下载。
- 一次抓取的 DNS 等待、重定向和正文读取共享超时，卡住的响应会被取消。
- 重叠自动保存使用独立临时文件，成功后输出完整 JSON；原子替换失败会清理临时文件。

## 边界与未覆盖项

这些测试不是完整安全审计。真实公众号平台兼容、真实公网 TLS/代理环境以及 Windows 上的浏览器操作仍需在目标环境验证。

抓取使用独立直连 Agent，不继承 HTTP_PROXY 等代理配置。保留原有 Clash fake-IP 域名解析兼容例外：解析出的 198.18.0.0/15 可用，但字面 IP URL 不允许。该兼容例外只适用于可信的本机代理/DNS 环境，不能理解为对所有非公网网段的完全隔离。

单次响应大小限制不等于总进程内存/并发配额。存储回归保证写入不互相损坏，不保证并发请求按用户发起顺序落盘；多客户端冲突解决、全局速率限制仍需单独设计。

测试不调用真实 AI、微信上传或草稿发布接口，不使用真实密钥。
