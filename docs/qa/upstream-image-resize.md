# Narrow upstream image resizing candidate

Base: `f0c819f34ad6c5134065242ddc9b1865212dc830`. This is a cloud implementation of the existing requested image-resize feature, not recovery of the unavailable desktop worktree. No deployment, publishing, production data, or credentials were used.

## Scope and contracts

- Native image references carry optional finite `displayWidth` between 10 and 100 percent. Normalization rejects invalid values. The compiler wraps each actual native image render site with its own reference, including kit output, rather than assuming global DOM image order. Empty slots, nested boxes and carousel frames retain their existing roles. Ending QR, replay, SVG/foreignObject and CSS background images are not resize targets.
- Imported HTML ordinary `img` elements, including small images, are addressed by the clicked image's exact position in an independently verified source/DOM image sequence. Duplicate source URLs remain distinct. Count/source mismatch rejects the action with a visible message. Existing slot/data-photo swap indexing is unchanged. This also permits reducing an HTML image to 10 percent and subsequently enlarging it; the existing decorative-image heuristic cannot make it disappear from the resize mapping.
- Native resize preserves source URL query parameters and source pixel dimensions. Existing image-reference behavior remains: swapping carries the width with the reference; replacement with a new reference without a width uses its default. This change does not silently impose destination-position sizing on replacement or crop.
- Editor controls are siblings outside the article and never serialized into saved HTML or compiled output. Drag preview changes only the live DOM, then restores the exact original style attribute (including absence). Successful pointer completion produces one store commit/undo entry. Pointer cancellation, lost capture and Escape cancel; stale document/block/DOM identity or source mapping refuses writes.
- Keyboard arrows, Shift acceleration, Home and End share the safety checks. Keyboard events revalidate the last measured DOM image, so same-frame removal, replacement or source changes cannot modify the document.
- The overlay is constrained to the intersection of image, canvas scrollport and viewport on all four sides. Its independent 44 px handle is anchored beside small images and clamped inside the canvas/viewport intersection. Only insufficient canvas space hides controls, not an image smaller than 44 px. A dynamic 400 px parent test verifies Home produces an actual 40×20 image while End and reselect/enlarge remain available. Width calculations remain based on the actual image parent, not the clipped rectangle. Black/white linear icon and 14 px label are locally scoped; no global theme changes.
